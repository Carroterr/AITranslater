# AITranslate 桌面实时字幕

在 Windows 上将浏览器、播放器和会议软件的系统声音翻译成可拖动、可置顶的悬浮字幕。默认原文为英语，译文为简体中文。译文也可选繁体中文。

## 启动

需要 Windows 10 或 11 和 64 位 Python 3.11。从项目目录打开 PowerShell，新环境执行以下命令。已有 `.venv` 可直接执行安装和启动两行。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

1. 填写 **DeepSeek API Key**，或通过 `DEEPSEEK_API_KEY` 环境变量提供。程序不会将密钥写入文件。选择翻译模式、适用场景、译文语言和播放设备，再点 **开始翻译**。本地英译中模式可选 GPU 或 CPU。云端翻译可设置预期的原文语言，供翻译模型参考。
2. 选用本地英译中时，第一次使用会下载所选设备需要的翻译模型。可以执行 `.\.venv\Scripts\python.exe local_translation.py` 预下载 CPU 权重。状态栏显示「正在采集」后，播放带人声的视频或音频。
3. 按住字幕拖到合适的位置。用设置窗口的滑杆调整 16–52 pt 字号，也可开关字幕显示和置顶。最小化设置窗口后，字幕仍可显示。
4. 默认开启 **显示原文**。每段原文显示在对应译文上方，识别出文字后立即显示。取消勾选即可只看译文，翻译过程中也可以切换。

**播放设备**默认使用 Windows 的默认输出。也可以选择播放器、浏览器或会议软件实际使用的耳机或扬声器。下拉列表每次展开时刷新。如果在运行中切换设备，停止翻译后重新选择，再开始翻译。

**上传音频格式**默认使用 OGG (Opus)，可切换为 WAV (PCM)。两种翻译模式共用此设置，切换格式前先停止翻译。

状态栏显示正在采集的设备。如果播放时显示「未检测到播放声音」，请在 Windows 声音设置的音量混合器中确认该应用的输出设备和音量。所选设备上的其他应用声音也会进入识别。

## 实时记录与对话历史

开始翻译时会自动打开 **本轮对话** 窗口，按顺序显示本轮识别出的原文和译文。停在底部时会跟随最新内容，向上滚动可以回看。停止后仍可查看本轮内容，下次开始时窗口会显示新一轮对话。

**始终置顶** 同时控制字幕和本轮对话窗口。可用 **显示实时记录** 隐藏或重新打开窗口。实时显示和文件保存可以分别开关。

在设置中勾选 **记录对话历史**。每次点 **开始翻译** 都会在 `%LOCALAPPDATA%\AITranslate\对话记录` 新建一个带时间的 UTF-8 `.txt` 文档。原文和译文带时间保存，草稿、定稿和跨段校对会更新文档中的同一条记录。停止翻译时会保存最新内容。

点 **查看对话历史** 可浏览已保存的内容，点 **打开文档文件夹** 可打开保存目录。保存默认关闭，开关状态会在重启后保留。翻译中关闭会暂停写入，再开启时继续写入本次会话的文档。

## 翻译模式

- **DeepSeek 识别 + 本地英译中**是默认模式。DeepSeek 识别英语语音，本地 M2M‑100 生成中文字幕。
- **DeepSeek 识别 + DeepSeek 译中文**先通过 DeepSeek 转写原文，再由 DeepSeek Flash 结合最近两段原文生成中文字幕。

两种模式共用同一个 DeepSeek API Key。切换模式时先停止翻译。

## 场景 Skill

- **看剧**默认开启。DeepSeek 翻译时会侧重口语自然度、人物称谓、语气和俚语。
- **面试**在字幕右侧显示 **面试问题总结**，用所选译文语言归纳面试题和追问，自动跳过重复表述。可滚动回看本次会话的问题。停止后可以继续查看，重新开始时会清空。需要切换场景时，先停止翻译。

腾讯会议等应用的对方声音由 **播放设备** 采集，在面试记录中标为 **A（系统播放）**。要记录自己的发言，开始翻译前勾选 **采集麦克风（B）**，然后选择会议软件正在使用的麦克风。麦克风采集默认关闭，开启后直接从 Windows 输入设备采集，会议软件静音时也可能录入本机发言。两路音频分别发送给 DeepSeek 转写。本轮对话、对话历史和保存的文本按发言开始时间排列，麦克风发言标为 **B（麦克风）**。

在两种模式中，面试场景都会额外把 A 的语音转写发给 DeepSeek 提取问题，这部分请求计入 API 用量。可编辑 `translation_skills.json` 中的场景规则，重启后生效。

## 实时更新方式

- Windows WASAPI 采集播放设备的声音，应用在内存中按设置编码语音片段并上传给 DeepSeek。DeepSeek 的语音接口逐段返回原语种文本，自动检测语言。云端翻译需另发一次文本请求。[DeepSeek 语音转文字文档](https://api-docs.deepseek.com/zh-cn/guides/asr/)
- 持续说话约 1.1 秒时请求首份草稿，之后每约 2.2 秒尝试更新。识别繁忙时，只保留最新的待处理草稿。停顿或单段达到 13 秒时提交完整片段，最终原文更新后会中止已过期的草稿翻译，有相同结果时会复用。
- 后续草稿和最终译文也会随生成进度更新。新译文生成到当前字幕长度时开始替换，完整译文生成后覆盖该行。没有句末标点的草稿以省略号结尾。
- OGG 能减少上传字节数。草稿和最终识别仍可能重复上传同一段语音，DeepSeek 按请求内的音频时长计费。两种模式均上传语音片段，云端翻译及面试总结还会发送文本。

## 跨段校对

默认开启，可在启动翻译前关闭。相邻两段间隔约 1.2 秒以内时，13 秒硬切或表示句子继续的标点、连接词会触发校对。两行定稿后，程序把这两段的原文、译文和最多五段更早的原文发给 DeepSeek。实时字幕照常显示，修正只应用于版本匹配的最近两行。

校对最多同时发一个请求。这项设置在两种翻译模式下都会产生额外的云端文本请求。

## 翻译设备

- **优先 GPU** 是默认选项。程序通过 DirectML 选择兼容 DirectX 12 的 AMD 或 NVIDIA 显卡，优先使用专用显存较多的卡。状态栏显示实际使用的设备。
- GPU 初始化或推理失败时切换为 CPU INT8。也可直接选择 **仅 CPU**。GPU 和 CPU 使用同一 M2M‑100 基础模型的不同格式，首次准备各约 2.47 GB 和 496 MB。

桌面版参考了 SimulCast 的流式字幕交互，采集、语音识别、翻译和窗口都在本项目实现。[SimulCast 上游仓库](https://github.com/muonuo/ai-simultaneous-interpreter) · [M2M‑100 原模型与 MIT 许可](https://huggingface.co/facebook/m2m100_418M) · [CPU INT8 权重](https://huggingface.co/ishiki-emo/mojicast-m2m100-ct2) · [GPU ONNX 权重](https://huggingface.co/Xenova/m2m100_418M) · [DirectML](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)
